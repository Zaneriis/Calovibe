### Choix recommandé après signal de dépendance

- `require('@modelcontextprotocol/client')` : `Client`, `StreamableHTTPClientTransport` ; version exacte **2.3.1**, Node >=20. L'export racine fournit ces symboles ; ne pas inventer un sous-chemin `/streamableHttp` non exporté par ce paquet. Les exports `require` pointent réellement vers `dist/index.cjs`, donc le test `.cjs` prévu est possible selon le paquet distribué.
- `require('@modelcontextprotocol/server')` : `Server`, `createMcpHandler` ; version **2.3.1**, Node >=20. Le bas niveau `Server` est marqué déprécié au profit de l'API haute, mais reste public pour les cas avancés. Ici deux handlers standard `tools/list` et `tools/call`, catalogue JSON Schema déjà contractuel et Ajv existant évitent 31 copies Zod ou un adaptateur de schéma supplémentaire. `setRequestHandler(method, handler)` accepte les méthodes standard ; la fabrique `createMcpHandler` accepte explicitement `Server` aussi bien que `McpServer`.
- `require('@modelcontextprotocol/node')` : `toNodeHandler`, `localhostHostValidation`, `localhostOriginValidation` ; version observée **2.1.1**, Node >=20, peer server ^2.3.0. Brancher sur `node:http.createServer`, écoute `127.0.0.1:0`. Cet adaptateur officiel évite de refaire la conversion Request/Response et les règles de flux. Candidat d'outillage de test seulement, sans changer le choix de service applicatif Fastify d'ADR01.
- Client : `versionNegotiation: { mode: { pin: '2026-07-28' } }`. La déclaration 2.3.1 confirme que le défaut reste `legacy` ; le mode `auto` peut aussi retomber sur l'ancien protocole. Serveur : `createMcpHandler(factory, { legacy: 'reject', responseMode: 'json' })` pour cette preuve stricte sans notifications. Vérifier les `_meta`/headers protocole captés à la frontière HTTP et le résultat de version du client ; ne pas appeler un simple `initialize` une preuve de la révision moderne. La fabrique est par requête et le handler gère ses transports ; utiliser sa méthode `close` au cleanup.
- Métadonnées et schémas : reprendre la résolution standard Swagger Parser déjà présente dans les tests API/MCP proposés, sans accès HTTP de résolution, et Ajv2020/formats full du contrat. Exporter sur le wire seulement la définition MCP portable ; `x-api` et scopes guident l'adaptateur local. Aucun `$ref` vers fichier/URN privé ne doit rester dans `tools/list`. Comparer les 31 définitions résolues au contrat et valider entrées/sorties avec les mêmes formats, notamment le format base64 contractuel. Le validateur client par défaut ne doit pas être présumé équivalent aux assertions spécifiques du contrat : injection `jsonSchemaValidator` ou assertions indépendantes à qualifier lors du code.
- Auth SYNTHÉTIQUE : tokens opaques de fixture en mémoire, aucune émission OAuth. `requireBearerAuth` officiel accepte un vérificateur et exige notamment `expiresAt` ; `handler.fetch` ne vérifie pas les headers seul, son `authInfo` est strictement transmis par l'appelant. L'étude supposait que la fabrique Server expose esolveScopeChallenge (corrigé lors de l'implémentation ci-dessous) pour répondre avant handler selon `request.params.name` et les scopes du catalogue ; la déclaration `ScopeChallengeHandler` prend `{request,authInfo}` et renvoie `{scopes}` ou `undefined`. Tester le 403 réel sans appel API. Côté client, `onInsufficientScope:'throw'` évite une tentative d'élévation interactive ; `requestInit` peut porter le Bearer synthétique sans `OAuthClientProvider`. Jeton absent → 401 réel, sans faux serveur d'autorisation ni tentative de login.
- Résultats : `resultType:'complete'`, `isError` et `structuredContent` conformes au contrat ; le bloc texte représente le même JSON. Le bas niveau expose `projectCallToolResult(result, outputSchema)` pour la projection de wire ; l'utiliser si nécessaire plutôt que réécrire le codec. Les erreurs d'arguments du domaine reconnu restent structurées selon contrat ; un outil inconnu/requête protocolaire invalide garde son erreur JSON-RPC.
